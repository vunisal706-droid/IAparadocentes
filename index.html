Las apps del libro

Las herramientas que aparecen en los capítulos, listas para descargar. Cada plantilla viene limpia, sin datos de ningún centro: la configuras con los tuyos y la publicas.

Cómo se usa esta páginaLos cuatro pasos, en orden
  1. Descarga aquí la app que quieras.
  2. Si guarda datos, crea tu Firebase siguiendo las guías (capítulo 8 del libro).
  3. Pasa la app por el configurador: pones los datos de tu centro y te da también las reglas de seguridad.
  4. Publícala en GitHub Pages (capítulo 6) y da de alta al claustro.

Puedes usar cualquier app tal cual o pedirle a la IA que la cambie a tu gusto: el libro explica cómo. El prompt de cada ficha sirve para eso.

Pulsa Ver para abrir la demostración, Descargar para llevarte la plantilla y QR para abrirla en el móvil.

Prompts del libro

Los cuarenta prompts del anexo A, listos para copiar. Cambia lo que va entre corchetes por tus datos. Dos reglas que lo hacen funcionar casi todo: un cambio cada vez y pedir siempre el archivo completo.

Firebase paso a paso

Lo del capítulo 8, con las pantallas de hoy. Solo hace falta para las apps que guardan datos compartidos.

Casi todas las apps guardan en Realtime Database; Convivencia+ usa Firestore. Las dos son de Firebase y la ficha de cada app dice cuál necesita.

1. Crear el proyecto de FirebaseSolo para Evaluaciones, Convivencia+ y Teletrabajo
  1. Entra en console.firebase.google.com con la cuenta de Google del centro.
  2. Pulsa Crear un proyecto y ponle un nombre claro, por ejemplo teletrabajo-losolivos. Google Analytics no hace falta: puedes desactivarlo.
  3. Ya dentro del proyecto, activa primero la base de datos (guía 2, o 2 bis para Convivencia+). Así el bloque de configuración traerá la dirección de la base de datos.
  4. En la portada del proyecto pulsa el icono web </> para registrar una app. Ponle un apodo y no marques Firebase Hosting.
  5. Copia el bloque const firebaseConfig = {…}. Es lo que pegarás en el configurador. Siempre puedes volver a verlo en ⚙ Configuración del proyecto → Tus apps.

Un proyecto por app. Cada proyecto tiene sus propias reglas de seguridad; si mezclas dos apps en uno, las reglas de una pueden romper la otra.

2. Activar Realtime DatabaseDonde se guardan los datos
  1. Menú lateral: Compilación → Realtime Database → Crear base de datos.
  2. Ubicación: Bélgica (europe-west1), para que los datos queden en la Unión Europea.
  3. Elige modo bloqueado. Las reglas de verdad las pegarás después.
  4. Arriba verás una dirección que termina en firebasedatabase.app. Si tu firebaseConfig no la trae, añádela como databaseURL.
  5. Pestaña Reglas: pega las reglas que te da el configurador y pulsa Publicar.

Si alguna vez lees ".read": true, ".write": true para toda la base de datos, no lo publiques: cualquiera con la dirección podría leer y borrar todo.

2 bis. Activar FirestoreSolo para Convivencia+
  1. Menú lateral: Compilación → Firestore Database → Crear base de datos.
  2. Ubicación en Europa (por ejemplo eur3 o europe-west1). No se puede cambiar después.
  3. Elige modo de producción.
  4. Pestaña Reglas: pega las reglas que te da el configurador y pulsa Publicar.

Convivencia+ no necesita databaseURL: con el firebaseConfig normal es suficiente.

3. Activar el acceso con usuarioAuthentication, para apps con entrada por IdEA
  1. Compilación → Authentication → Comenzar.
  2. Pestaña Sign-in method → Correo electrónico/contraseña → activa solo el primer interruptor → Guardar.
  3. No hace falta crear usuarios a mano: cada app los crea desde su panel (Teletrabajo en Personal, Evaluaciones en Ajustes → Gestionar profesorado, Convivencia+ en Configuración).

Los "correos" del tipo usuario@micentro.local no existen ni reciben nada: son solo el identificador interno que Firebase necesita.

Configurador

Subes la plantilla, pegas tu configuración de Firebase y los datos de tu centro, y te devuelve la app preparada y sus reglas de seguridad.

4. Configurar la appCon el configurador, justo debajo
  1. Descarga la plantilla desde el apartado Las apps del centro y descomprímela.
  2. Abre el configurador y sube el index.html.
  3. Si la app usa Firebase, pega el firebaseConfig. Después rellena los datos del centro.
  4. Descarga el index.html configurado y sustituye con él al de la carpeta.
  5. Copia las reglas y publícalas en Firebase (guía 2, último paso).

Cuadra Horarios, Mis Lecturas, PDF a Markdown y Word y el Troglodita no llevan configuración: úsalos tal cual. ¿Prefieres configurar a mano las demás? Abre el index.html con el Bloc de notas: al principio verás el bloque CONFIGURACIÓN DEL CENTRO. Cambia solo lo que hay entre comillas.

Todo ocurre en tu navegador: el archivo no se sube a ningún sitio. Cuadra Horarios, Mis Lecturas, PDF a Markdown y Word y el Troglodita no necesitan configuración.

2. Primera entrada y alta del claustro

  

      
6. Primera entrada y alta del claustroPara apps con acceso por usuario IdEA

      

        
    
          
  1. Abre la app publicada. La primera vez solo existe la persona administradora que pusiste en el configurador.
    2. 
          
  2. Entra con su usuario IdEA. La cuenta de administración se crea sola esa primera vez.
    3. 
          
  3. Desde el panel de personal de la app, da de alta a cada docente con su nombre y usuario IdEA.
    4. 
          
  4. Comparte la dirección o el código QR con el claustro. Cada persona entra eligiendo su nombre y escribiendo su IdEA.
    5. 
        

        
El usuario IdEA se usa como clave para que nadie tenga que recordar otra contraseña. Es cómodo, pero no es secreto: úsalo para la gestión interna del claustro, no para información sensible.

      

    

  
3. Cuando algo no funciona

  

      
Sale "Esta app aún no está configurada"

      
Falta algún dato imprescindible en el bloque de configuración: normalmente la apiKey, la databaseURL o el usuario IdEA de la persona administradora. Vuelve a pasar el archivo por el configurador y comprueba que todos los indicadores están en verde.

    

      
No guarda o aparece "PERMISSION_DENIED"

      
Casi siempre son las reglas: no se han publicado, se pegaron las de otra app o se publicaron con un IdEA de administración distinto. Copia de nuevo las del configurador, sustituye todo el contenido de la pestaña Reglas y pulsa Publicar.

    

      
Error "auth/operation-not-allowed"

      
No está activado el método Correo electrónico/contraseña en Authentication (guía 3).

    

      
"La contraseña debe tener al menos 6 caracteres"

      
Firebase no acepta claves de menos de 6 caracteres. Si algún usuario IdEA es más corto, esa persona necesitará una cuenta creada a mano desde la consola, en Authentication → Users.

    

      
Con la cuenta educativa no me deja entrar en Firebase o Gemini

      
En las cuentas corporativas o educativas, la administración puede tener bloqueados algunos servicios de Google. Crea una cuenta de Google para el centro y úsala solo para esto.
